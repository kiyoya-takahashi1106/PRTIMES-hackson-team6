# メディア推薦ロジック

既存の「自動選択」UIはそのまま使い、内部ロジックだけを推薦式に差し替えます。

## 目的

作成中のプレスリリースに近い「過去の成功プレスリリース」を探し、それらが掲載されたメディアを推薦します。

## 推薦の流れ

1. 今回の企業情報から `industry` と `ipo_type` を取得する
2. `直近5年 x 同industry x 同ipo_type` の過去投稿を取得する
3. 各投稿の掲載メディアと広告換算値を集計する
4. 広告換算値の上位10%を成功投稿とする
5. 今回の `title + lead_paragraph + body` を Embedding 化する
6. 成功投稿との Cosine Similarity を計算する
7. 類似度上位30投稿を取得する
8. その30投稿が掲載されたメディアを集める
9. メディアごとの最大類似度で順位付けする
10. 既存の自動選択結果として返す

## 成功投稿の定義

- 成功判定は推薦実行時に毎回計算する
- `success_flag` や `percentile` は DB に保存しない
- 投稿単位の広告換算値は、掲載メディアごとの広告換算値の合計
- 比較対象内で広告換算値上位10%を成功投稿とする

## Embedding

- 対象テキスト: `title + lead_paragraph + body`
- モデル: `text-embedding-3-large`
- 次元数: `1024`
- 類似度: Cosine Similarity
- API キー: `OPENAI_API_KEY`

過去投稿の Embedding は事前生成し、`release.embedding` に保存します。
対象は `embedding IS NULL` の投稿だけにして、再実行しやすいバッチ処理にします。

## メディアの扱い

- メディア識別は可能な限り `media_id` を使う
- `site_name` 文字列だけの判定は避ける
- 同じメディアが複数回出た場合は重複表示しない
- 推薦スコアは、そのメディアに紐づく投稿の最大類似度

## fallback

次の場合は既存の自動選択ロジックへ戻します。

- 比較対象の投稿がない
- 成功投稿がない
- Embedding 済みの成功投稿がない
- 類似上位30投稿から掲載メディアを取得できない

## 実装方針

- 手動選択は変更しない
- 自動選択の内部処理だけ変更する
- 新しい専用画面は作らない
- 既存 DB、既存 API、既存 UI を優先して使う
- データ不足時に無理な推薦結果を作らない
